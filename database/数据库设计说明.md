# 个人智能健康助手数据库设计说明

## 概述

本数据库设计基于 A2A-MCP Server 框架和《个人智能健康助手可行性方案》，为个人智能健康助手系统提供完整的数据存储解决方案。

### 技术规格

- **数据库类型**: MySQL 8.0+
- **字符集**: utf8mb4
- **排序规则**: utf8mb4_unicode_ci
- **存储引擎**: InnoDB

## 数据库结构

### 1. 用户管理模块

#### 1.1 users (用户基本信息表)

- **主要功能**: 存储用户的基本账户信息
- **关键字段**:
  - `user_id`: 用户唯一标识符
  - `username`: 用户名
  - `email`: 邮箱地址
  - `phone`: 手机号码
  - `status`: 账户状态

#### 1.2 user_profiles (用户个人档案表)

- **主要功能**: 存储用户的详细个人信息和健康基础数据
- **关键字段**:
  - `real_name`: 真实姓名
  - `gender`: 性别
  - `birth_date`: 出生日期
  - `height/weight`: 身高体重
  - `blood_type`: 血型
  - `allergies`: 过敏史
  - `chronic_diseases`: 慢性疾病史
  - `family_history`: 家族病史

### 2. 健康档案管理模块

#### 2.1 health_records (健康档案主表)

- **主要功能**: 存储用户的各类健康档案记录
- **记录类型**:
  - `prescription`: 处方单
  - `test_report`: 检查报告
  - `medical_record`: 病历
  - `hospital_record`: 住院记录
  - `vaccination`: 疫苗接种
  - `surgery`: 手术记录
- **安全特性**:
  - `content_encrypted`: 加密的原始内容
  - `extracted_data_encrypted`: 加密的提取数据
  - `file_hash`: 文件完整性校验

#### 2.2 health_record_attachments (健康档案附件表)

- **主要功能**: 管理健康档案的附件文件
- **支持功能**:
  - 多种文件类型支持
  - 缩略图生成
  - 上传状态跟踪

### 3. 用药管理模块

#### 3.1 medications_base (药物基础信息表)

- **主要功能**: 存储药物的基础信息库
- **包含信息**:
  - 药物名称和通用名
  - 生产厂家和规格
  - 适应症和禁忌症
  - 副作用和药物相互作用
  - 储存条件

#### 3.2 user_medications (用户用药记录表)

- **主要功能**: 记录用户的具体用药情况
- **关键功能**:
  - 用药剂量和频率管理
  - 用药周期跟踪
  - 剩余药量监控
  - 处方来源记录

### 4. 提醒管理模块

#### 4.1 reminders (提醒主表)

- **主要功能**: 管理各类健康提醒
- **提醒类型**:
  - `medication`: 用药提醒
  - `checkup`: 体检提醒
  - `appointment`: 预约提醒
  - `exercise`: 运动提醒
  - `diet`: 饮食提醒
- **重复模式**:
  - 单次、每日、每周、每月、自定义

#### 4.2 medication_reminders (用药提醒详情表)

- **主要功能**: 专门管理用药提醒的详细信息
- **特殊功能**:
  - JSON 格式存储多个提醒时间点
  - 与用药记录关联
  - 支持复杂的用药计划

#### 4.3 reminder_logs (提醒执行记录表)

- **主要功能**: 记录提醒的执行情况
- **状态跟踪**:
  - `pending`: 待发送
  - `sent`: 已发送
  - `completed`: 已完成
  - `skipped`: 已跳过
  - `failed`: 发送失败

### 5. 健康咨询模块

#### 5.1 consultation_sessions (咨询会话表)

- **主要功能**: 管理用户与 AI 智能体的咨询会话
- **智能体类型**:
  - `health_advisor`: 健康顾问
  - `medication_assistant`: 用药助手
  - `records_manager`: 档案管理员
  - `summary_generator`: 摘要生成器

#### 5.2 consultation_messages (咨询消息表)

- **主要功能**: 存储咨询会话中的所有消息
- **支持功能**:
  - 多种内容类型（文本、图片、文件、结构化数据）
  - 元数据和附件管理
  - Token 使用量统计
  - 响应时间监控

### 6. 就诊摘要模块

#### 6.1 visit_summaries (就诊摘要表)

- **主要功能**: 存储和管理就诊摘要信息
- **核心内容**:
  - 主诉和症状描述
  - 诊断结果和治疗方案
  - 开具药物信息
  - 随访指导
- **生成方式**:
  - 手动录入
  - AI 助手生成
  - OCR 提取

### 7. 系统管理模块

#### 7.1 agent_configs (智能体配置表)

- **主要功能**: 管理各个 AI 智能体的配置信息
- **预置智能体**:
  - 健康档案管理员 (端口 10010)
  - 健康顾问 (端口 10011)
  - 用药提醒助手 (端口 10012)
  - 就诊摘要生成 (端口 10013)

#### 7.2 system_logs (系统日志表)

- **主要功能**: 记录系统操作日志
- **日志级别**: DEBUG, INFO, WARN, ERROR, FATAL

## 高级功能

### 视图 (Views)

1. **user_health_overview**: 用户健康概览视图

   - 整合用户基本信息、健康档案数量、活跃用药数量、活跃提醒数量

2. **medication_reminder_overview**: 用药提醒概览视图
   - 整合用药提醒信息和执行统计

### 存储过程 (Stored Procedures)

1. **CreateUserProfile**: 创建用户完整档案

   - 事务性创建用户基本信息和档案信息

2. **GetActiveMedications**: 获取用户活跃用药
   - 查询用户当前正在使用的药物信息

### 触发器 (Triggers)

1. **tr_health_records_update**: 健康档案更新时间触发器
2. **tr_user_medications_status**: 用药记录状态变更触发器
   - 自动处理过期用药的状态变更

### 索引优化

- 单列索引：用户 ID、时间字段、状态字段
- 复合索引：用户+类型+时间的组合查询优化
- 全文索引：支持内容搜索（可选）

## 安全特性

### 数据加密

- 敏感健康数据采用 BLOB 字段加密存储
- 文件完整性校验（SHA-256 哈希）
- 用户隐私信息保护

### 访问控制

- 外键约束确保数据一致性
- 软删除机制（is_deleted 字段）
- 用户数据隔离

### 审计跟踪

- 完整的操作日志记录
- 时间戳跟踪（created_at, updated_at）
- 用户行为监控

## 在 Navicat 中的使用步骤

### 1. 创建数据库

1. 打开 Navicat，连接到 MySQL 服务器
2. 右键点击连接，选择"新建数据库"
3. 数据库名：`personal_health_assistant`
4. 字符集：`utf8mb4`
5. 排序规则：`utf8mb4_unicode_ci`

### 2. 执行 SQL 脚本

1. 打开数据库
2. 点击"查询"按钮，新建查询
3. 复制`personal_health_assistant.sql`文件内容
4. 粘贴到查询窗口
5. 点击"运行"执行脚本

### 3. 验证数据库结构

1. 刷新数据库，查看表结构
2. 检查表之间的外键关系
3. 验证索引和约束
4. 查看预置的配置数据
