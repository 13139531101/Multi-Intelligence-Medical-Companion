# 个人智能健康助手 - 开题PPT大纲

## 封面页
- 项目名称：基于A2A-MCP架构的个人智能健康助手
- 副标题：多智能体协同的私密健康管理平台
- 技术栈：A2A框架 + MCP协议 + 多模态AI
- 日期：2025-11-22

## 第1页：项目愿景与痛点
### 核心问题
- 医疗信息碎片化：病历、检查报告、用药记录分散
- 医患沟通效率低：就诊时信息传递不完整
- 健康管理困难：缺乏系统化的个人健康档案

### 解决方案
- 构建统一的个人健康知识库
- 智能辅助医患沟通
- 全生命周期健康管理

### 模拟案例：糖尿病患者健康管理
- **场景**：45岁男性，2型糖尿病患者，需要定期监测和管理
- **系统功能展示**：
  - 用药提醒：定时推送二甲双胍服药提醒（500mg，每日两次）
  - 饮食建议：根据血糖数据推荐低GI食物组合
  - 就诊辅助：生成结构化就诊摘要，包含近期血糖趋势和用药记录

## 第2页：技术架构总览
### A2A-MCP双核架构
- **A2A框架**：多智能体协同工作流
- **MCP协议**：标准化工具调用接口
- **技术优势**：模块化、可扩展、安全可靠

| +-----------------+ |
| | Medication      | | ⇄ MCP → ReminderTool → 定时任务

| |                 | | ⇄ MCP → PostgreSQL数据库
| +-----------------+ |
| +-----------------+ |

## 第3页：核心功能模块
### 四大核心功能
1. **健康档案智能构建**
   - 多模态信息录入（OCR+文件+手动）
   - 结构化数据提取与存储
   - **A2A负责**：多智能体协同工作流编排，协调OCR识别、数据验证、存储入库流程
   - **MCP负责**：标准化OCR工具调用、文件解析接口、数据库操作协议

2. **智能健康咨询**
   - 基于个人病史的症状分析
   - 健康知识问答系统
   - **A2A负责**：症状推理决策链，多专家智能体协同诊断，风险评估
   - **MCP负责**：知识库查询接口，AI模型调用协议，历史数据检索标准化

3. **辅助就医沟通**
   - 就诊前摘要自动生成
   - 医患信息高效传递
   - **A2A负责**：摘要生成智能体协作，关键信息提取优先级排序
   - **MCP负责**：文档模板标准化，信息导出格式协议，打印/分享接口

4. **用药与复诊管理**
   - 智能用药提醒
   - 药品库存预警
   - 复诊计划管理
   - **A2A负责**：用药提醒智能调度，库存预警决策，复诊时间智能推荐
   - **MCP负责**：定时任务协议，推送通知接口，日历集成标准化

- `AIAnalysisTool`：智能分析与摘要

## 第6页：系统级业务流程演示
### 基于A2A-MCP的健康管理协同流程
1. **健康档案智能构建流程**
   - 用户上传医疗文档（病历、检查报告、处方等）
   - OCRTool识别文档内容，DataExtractionTool提取关键信息
   - HealthRecordsManager验证数据并存储到健康档案数据库
   - 同步更新记忆系统，构建个人健康知识图谱

2. **智能健康咨询服务流程**  
   - 用户输入健康问题或症状描述
   - HealthAdvisor调用KnowledgeTool检索医疗知识库
   - 结合个人健康档案，使用DiagnosisTool进行分析推理
   - 生成个性化健康建议和风险评估报告

3. **用药与复诊管理流程**
   - MedicationReminder监控用药计划和复诊时间
   - ReminderTool定时发送用药提醒和复诊通知
   - 库存预警机制监测药品存量，NotificationTool推送预警
   - 管理长期用药计划和周期性复诊安排

4. **辅助就医沟通流程**
   - VisitSummaryGenerator分析就诊需求和历史记录
   - DocumentTool生成结构化就诊摘要和问题清单
   - AIAnalysisTool提供医患沟通建议和注意事项
   - 准备就诊所需材料和历史资料汇总

### A2A-MCP协同工作模式
```
[用户请求] → [API网关] → MCP路由分发
    │
    ├─ HealthRecordsManager → OCRTool/DataExtractionTool/StorageTool（档案构建）
    │
    ├─ HealthAdvisor → KnowledgeTool/DiagnosisTool（健康咨询）
    │  
    ├─ MedicationReminder → ReminderTool/NotificationTool（用药管理）
    │
    └─ VisitSummaryGenerator → DocumentTool/AIAnalysisTool（就医辅助）
        ↓
[结果聚合] → [响应用户]
```

### 智能体并行处理机制
- **独立任务处理**：各智能体并行处理不同类型的用户请求
- **数据共享协同**：通过统一数据库和记忆系统实现数据共享
- **结果聚合输出**：多个智能体的处理结果聚合后统一返回用户
- **异常处理**：单个智能体故障不影响其他功能模块正常运行

### 关键衔接点
- 档案构建→咨询：异常指标、缺失信息、新病史触发
- 咨询→用药/复诊：行动计划落地为提醒与安排
- 用药/复诊→就医：持续异常或到期复诊触发就医准备
- 就医→档案更新：新增检查/处方回流，驱动下一轮闭环

## 第7页：技术难点与解决方案
### 难点1：医疗信息结构化提取
- **挑战**：医疗文档格式多样，信息非结构化
- **解决方案**：
  - 定制化的OCR后处理管道
  - 基于规则+AI的混合提取算法
  - 医疗实体识别与关系抽取

### 难点2：多智能体协同一致性
- **挑战**：智能体间状态同步与数据一致性
- **解决方案**：
  - 分布式事务管理
  - 消息队列保证最终一致性
  - 智能体状态快照与恢复

### 难点3：隐私安全与合规性
- **挑战**：健康数据敏感性要求高
- **解决方案**：
  - 端到端加密存储
  - 数据最小化原则
  - 合规的数据处理流程

## 第8页：技术栈与关键技术实现
### 后端技术栈
- **A2A框架**：FastMCP + A2AServer核心库
- **Python生态**：FastAPI、SQLAlchemy、Pydantic
- **AI模型集成**：DeepSeek、OpenAI、智谱AI多模型支持
- **数据库**：PostgreSQL + 向量数据库（记忆系统）
- **异步处理**：asyncio + aiohttp高性能异步架构

### 前端技术栈
- **React 18**：函数式组件 + Hooks
- **Material-UI**：现代化UI组件库
- **状态管理**：Recoil原子状态管理
- **构建工具**：Vite + TypeScript
- **路由**：React Router v6
- **HTTP客户端**：Axios + Fetch Event Source

### 关键技术实现
#### OCR技术栈
- 阿里云OCR服务深度集成
- 医疗文档专用预处理管道
- 多语言支持与智能纠错

#### AI分析能力
- 多模型协同推理（DeepSeek/OpenAI/智谱）
- 症状-疾病关联分析算法
- 用药合理性检查引擎
- 健康趋势预测模型

#### 实时通信机制
- WebSocket长连接保活
- SSE（Server-Sent Events）实时推送
