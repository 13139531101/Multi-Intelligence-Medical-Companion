# 开题报告：基于 A2A-MCP 架构的个人智能健康助手设计与实现

## 1. 选题的目的、意义及国内外对本课题涉及问题的研究现状

### 1.1 选题目的与意义

随着人们健康意识的提升和医疗数据的爆炸式增长，个人健康管理面临着严峻挑战：医疗信息碎片化严重，病历散落在不同机构；医患沟通效率低下，患者难以准确描述病史；且普通人缺乏专业知识，难以进行系统化的全生命周期健康管理。

本课题旨在开发一套“基于 A2A-MCP 架构的个人智能健康助手”，具有重要的现实意义：

1.  **构建统一健康知识库**：利用多模态技术将纸质和电子医疗文档结构化，形成完整的个人健康档案。
2.  **提升医患沟通效率**：通过智能生成就诊摘要，辅助患者与医生进行高效、准确的信息传递。
3.  **实现全生命周期管理**：提供用药提醒、复诊管理及智能健康咨询，通过技术手段赋能个人健康管理，降低医疗信息管理成本。
4.  **技术创新验证**：探索 A2A（Agent-to-Agent）框架与 MCP（Model Context Protocol）协议在垂直领域的应用潜力。

### 1.2 国内外研究现状

#### 1.2.1 国际研究现状

国际市场上，个人智能健康助手正从单一的“症状自查”向“全能型健康管家”演进。市场研究显示，医疗智能虚拟助手市场正以每年约 25% 的速度增长。

- **产品案例**：**Sync.MD** 是目前的典型代表，其搭载的 **Sync.Sense™** 个人健康助手，结合了先进的 OCR（光学字符识别）技术，能够自动识别并数字化用户的纸质医疗记录，用户可以通过对话方式查询自己的病历细节，实现了“病历对话”的交互模式。
- **技术趋势**：随着大语言模型（LLM）的发展，如 Google 的 Med-PaLM 2 等专用模型的出现，海外产品正致力于提高医学建议的准确性与同理心，并探索 AI Agent（智能体）在预约挂号、保险理赔等复杂任务中的自动化执行能力。

#### 1.2.2 国内研究现状

国内的互联网医疗巨头也在积极布局 AI 健康助手，侧重于利用庞大的医疗数据构建垂域大模型，服务于“互联网+医疗”生态。

- **行业标杆**：**平安健康（原平安好医生）** 推出的 **“平安芯医”** 名医数字分身，能够提供 7x24 小时的健康咨询服务。其最新研发的 **“平安医博通”** 多模态医疗大模型，近期更是接入了 **DeepSeek** 等先进推理模型，在辅助诊断（准确率超 95%）、体检报告解读（精准率 98%）及慢病管理（如糖尿病饮食干预）方面表现卓越。
- **发展特点**：国内产品多依托于大型保险或医院集团，形成了“AI 导诊 + 线上问诊 + 线下就医”的闭环服务。例如，通过 AI 进行大规模的慢病人群管理和用药合规性质控。

#### 1.2.3 总结与本课题切入点

综上所述，现有的国内外产品在“单点技术”（如 OCR 识别、问诊对话）上已较为成熟，但仍存在以下局限：

1.  **数据分散**：大多数产品服务于特定的医疗机构或保险生态，用户的全生命周期健康数据难以统一管理。
2.  **隐私顾虑**：中心化的云端服务让用户对敏感的病历数据上传存有顾虑。
3.  **协作能力不足**：目前的助手多为单一的对话窗口，缺乏多智能体（A2A）之间的专业分工与协作（如营养师、全科医生、心理咨询师的会诊模式）。

本课题旨在基于 **A2A (Agent-to-Agent)** 架构与 **MCP (Model Context Protocol)** 协议，设计一款**以用户为中心**的个人智能健康助手。它不仅集成了类似 Sync.MD 的病历 OCR 与档案管理功能，更通过多智能体协作机制，模拟真实医疗团队的会诊流程，旨在打破数据孤岛，为用户提供更私密、更全面、更具个性化的健康管理服务。

## 2. 本课题主要研究方法、研究手段和需要重点研究的问题及解决的思路

### 2.1 主要研究内容与目标

本研究致力于设计并实现一个安全、私密、可扩展的个人智能健康助手系统。主要研究内容包含五大核心模块：

1.  **健康档案智能构建**：支持 OCR 识别与多模态录入，构建个人健康知识图谱。
2.  **智能健康咨询**：基于个人病史提供症状分析与风险评估，集成权威医疗知识库。
3.  **辅助就医沟通**：分析历史记录与当前需求，自动生成结构化就诊摘要。
4.  **用药与复诊管理**：监控用药计划与库存，提供智能提醒与复诊规划。
5.  **健康趋势可视化分析**：基于长期数据自动提取关键指标（如血压、血糖），利用图表呈现变化趋势，辅助发现风险点。

### 2.2 研究方法与技术手段

本项目采用 **A2A-MCP 双核架构**：

- **架构设计**：A2A 层负责智能体协作（档案管理、健康顾问、用药提醒、摘要生成）；MCP 层负责标准化工具调用（OCR、数据库、AI 模型）。
- **后端技术**：Python, A2A 框架 (FastMCP + A2AServer), FastAPI, SQLAlchemy, Pydantic。
- **AI 与数据**：集成 DeepSeek/OpenAI 等多模型，使用 PostgreSQL 存储结构化数据，向量数据库存储语义记忆，调用阿里云 OCR 服务。
- **前端技术**：微信小程序原生开发 (WXML, WXSS, JS/TS)，使用 Echarts-for-Weixin 实现数据可视化。
- **通信技术**：WebSocket/SSE 实现前后端实时双向通信。

### 2.3 重点研究问题及解决思路

1.  **医疗信息结构化提取**

    - **问题**：医疗文档（病历、化验单）非结构化程度高，格式繁杂。
    - **思路**：开发定制化的 OCR 后处理管道，结合规则引擎与 AI 大模型进行实体识别与关系抽取，提高提取准确率。

2.  **多智能体协同一致性**

    - **问题**：多智能体并行工作时需保证状态同步与数据一致性。
    - **思路**：采用分布式事务管理思想，引入消息队列机制保证最终一致性，并设计智能体状态快照与恢复机制。

3.  **隐私安全与合规性**
    - **问题**：个人健康数据极其敏感。
    - **思路**：坚持数据最小化原则，实施端到端加密存储，确保设计符合数据安全法规。

## 3. 工作方案及进度计划

### 3.1 工作方案（实施路径）

1.  **数据层建设**：搭建 PostgreSQL 与向量数据库，设计医疗数据模型。
2.  **MCP 工具开发**：封装 OCR、存储、检索、通知等基础能力的 MCP 接口。
3.  **智能体构建**：基于 A2A 框架开发四大核心智能体，定义交互接口与 Prompt 工程。
4.  **系统集成**：实现 API 网关，打通微信小程序前端与智能体集群的通信，完成端到端流程测试。

### 3.2 预期成果

1.  **软件系统**：一套完整的个人智能健康助手微信小程序（含前后端）。
2.  **技术文档**：系统架构设计文档、API 接口文档及部署手册。
3.  **演示 Demo**：能够展示从病历上传识别到生成就诊摘要、智能问答及健康趋势图查看的完整业务闭环。

### 3.3 进度计划

- **第一阶段（当前）**：完成 A2A-MCP 基础框架搭建，集成 OCR 工具，设计基础健康数据模型。
- **第二阶段**：实现多智能体协同机制，开发健康咨询与用药提醒核心功能。
- **第三阶段**：完成就诊摘要生成功能，开发微信小程序前端及健康趋势可视化模块，进行移动端适配与全面测试。
