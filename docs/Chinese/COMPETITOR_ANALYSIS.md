# 与同类产品的差距分析

> 目的：找出**真正值得补的**差距，而不是"看起来没有的"。
>
> **不选框架**（Dify / AutoGen / CrewAI 是工具，不是产品）。
> 选**真实部署的同类产品**——医疗健康方向优先（直接对标 PHA），其次泛用类 agent 产品。
>
> 判断标准：star 高意味着有生产用户在用；数字指标有出处的才可信。

---

## 一、同类医疗健康 AI Agent 产品

### 1.1 Color Health（对标性最强）

**产品**：乳腺癌筛查助手（Google Cloud + Gemini 2.5 + ADK）
**用户**：40+ 岁女性，高风险人群

| 维度 | Color Health | PHA |
|---|---|---|
| 核心能力 | 筛查资格评估 + 预约 + 问答 + 提交临床复核 | 健康问答 + 档案操控 + 就医记录 |
| 多 Agent | ADK 框架，多步骤协调 | 四层协议分层（MCP/A2A/AG-UI/ANP） |
| RAG | 未披露 | 18 条四组消融，MRR 0.95 |
| 人类复核 | ✅ **临床医生复核**（Color Medical 医疗集团） | ❌ 无 |
| 隐私合规 | Google Cloud HIPAA | 需自查 |
| 落地规模 | 商业产品，Google Cloud 背书 | 个人项目 |
| 评测 | 未披露 | **拒答 fpr=0.0**，含 3 条 no_answer |

**PHA 差距**：没有**临床复核通道**。用户拿到的是 AI 的直接输出，没有"AI → 医生 → 用户"的闭环。

---

### 1.2 IKS Health（多 Agent 协作代表）

**产品**：医疗行政自动化平台（Google Cloud + Gemini + ADK，多 Agent）
**用户**：医院/诊所行政人员

| 维度 | IKS Health | PHA |
|---|---|---|
| 核心能力 | 环境文档 → 编码 → 事先授权 → 提交保险 | 健康问答 + 档案检索 + 页面操控 |
| Agent 数量 | **多 Agent 协作**（文档/编码/授权/提交各司其职） | 4 个领域 Agent（host + 3 sub） |
| HITL | ✅ **按需人工复核**（医学必要性判断） | ✅ `__interrupt__` 三选项（但没有接入临床复核） |
| 自主率 | **80% 常规任务自动化** | 辅助性质，非自动化 |
| 效果指标 | 80% 自动化 | 未量化 |
| 合规 | HIPAA + Google Cloud | 需自查 |

**PHA 差距**：IKS 的多 Agent 是**分工协作**（每个 Agent 做一类任务），我们的 4 个 Agent 是**按领域划分**（每个 Agent 覆盖一个业务域）。前者更适合复杂行政流程，后者更适合单一入口导航。

---

### 1.3 Retell AI（语音 Agent 产品标杆）

**产品**：企业语音 Agent 平台
**用户**：医疗、物流、电商来电自动化

| 维度 | Retell AI | PHA |
|---|---|---|
| 核心能力 | 来电自动化，<600ms 延迟 | 文字交互，无语音 |
| 合规 | **SOC 2 + HIPAA** | ❌ 无认证 |
| 成本 | $0.07-0.33/分钟 | — |
| 案例 | Medical Data Systems：$28 万/月自动化催收；Pine Park Health：NPS 提升 38% | — |
| 多轮记忆 | ✅ 跨通话记忆（同一联系人历史） | ✅ LangGraph thread_id 隔离 |
| 实时 | ✅ Webhook 函数调用 | ❌ 无 |

**PHA 差距**：完全没有语音通道；没有 HIPAA/SOC 2 认证。

---

### 1.4 联影智能（国内影像 AI Agent）

**产品**：一扫多查 Agent（一次扫描查多种异常）
**用户**：放射科

| 维度 | 联影智能 | PHA |
|---|---|---|
| 核心能力 | 73 项胸部异常 / 47 项脑部异常，单次扫描全量检出 | 健康记录问答 + 档案管理 |
| Agent 类型 | **单次扫描 → 多 Agent 并行分析 → 汇总** | 单入口 → 领域 Agent 路由 |
| 评测 | **专业指标**（准确率、灵敏度、特异度） | RAG MRR，但无临床指标 |
| 数据源 | 影像（DICOM） | 文本记录 |

**PHA 差距**：没有影像处理能力；临床评测指标为零。

## 二、泛用类 AI Agent 产品（工程参考）

### 2.1 Intercom Fin（客服 Agent 标杆）

**产品**：AI 客服，解决 50-70% 询问无需人工介入
**用户**：SaaS 企业客户

| 维度 | Intercom Fin | PHA |
|---|---|---|
| 自主率 | **50-70%** 无需人工 | 问答辅助，非自动化 |
| 多轮对话 | ✅ | ✅ |
| 升级路径 | ✅ 无缝转人工，context 全携带 | ❌ 无人工升级通道 |
| 知识库 | 绑 Intercom KB，RAG 已集成 | 自建 RAG，有评测 |
| 多语言 | **45+ 语言** | ❌ 无 |
| 路由 | 意图分类 → 最优 Agent | 三层路由（layer1/2/3） |
| 评测 | 按 resolution 计费，效果可量化 | 18 条 RAG + 7 条 smoke，无业务指标 |

**PHA 差距**：没有**人工升级通道**；没有多语言；没有"按效果量化"（多少 % 用户满意）。

---

### 2.2 Linear AI Agent（工程工具 Agent 代表）

**产品**：从 Intercom/Zendesk/Gong 对话自动创建议题
**用户**：工程团队

| 维度 | Linear AI Agent | PHA |
|---|---|---|
| 核心能力 | 对话 → 结构化 issue（自动抽取标题/描述/优先级/团队） | 对话 → 档案操作 |
| 记忆 | ✅ 跨对话（同一用户历史） | ✅ thread_id 隔离 |
| 触发方式 | **被动**（收到消息才处理） | 主动（用户发消息） |
| 去重 | ✅ 自动合并重复 issue | ❌ 无 |
| 路由 | 意图分类 → 相关团队 | layer1/2/3 三层 |
| 执行 | Linear API 写回 | 工具调用 |

**PHA 差距**：Linear 的输出是**结构化数据写回外部系统**（issue），我们的输出是**状态变更 + UI 操控**。PHA 更复杂，因为 UI 操控有幂等性问题。

## 三、按优先级排序的差距清单

### 🔴 面试会被直接问住、或生产门槛的（优先补）

| 差距 | 为什么重要 | 怎么快速补 |
|---|---|---|
| **无临床复核通道** | Color Health 和 IKS Health 都有"AI → 医生 → 用户"闭环，纯 AI 回答在医疗场景有法律风险 | 最小实现：在 HITL `__interrupt__` 基础上加一个"提交医生复核"选项，模拟 IKS Health 的"按需人工复核" |
| **无 HIPAA/SOC 2 合规认证** | 医疗数据处理的基本门槛 | 诚实说"是个人项目，合规认证需要企业资质"；但架构上要做到**数据不落地本地**（目前已走 DashScope HTTP）|
| **无语音通道** | Retell AI 已经是标配，医疗场景尤其需要语音（老年人/不方便打字）| 诚实说"下一步计划"，不需要现在做 |

### 🟡 泛用功能差距（面试能说清楚就行）

| 差距 | 现状 | 面试怎么说 |
|---|---|---|
| **人工升级通道缺失** | 用户拿到 AI 输出就结束了 | "Intercom Fin 的无缝转人工是成熟产品的标志，我目前的场景是辅助问答，还没有接人工通道的计划" |
| **无多语言** | 45+ 语言 vs 只有中文 | "目前聚焦中文健康问答，多语言需要独立 RAG 和 Prompt 适配" |
| **自主率未量化** | Intercom Fin 50-70%，IKS 80%，我们没有 | "我没有真实用户量，所有自主率数字都是模拟环境测的" |
| **无去重/合并逻辑** | Linear AI Agent 会自动合并重复 issue | "这个能力在单用户场景优先级低" |

### 🟢 不需要补的

| 差距 | 为什么不需要补 |
|---|---|
| 影像处理能力 | 联影的场景，不是 PHA 的场景 |
| 多 Agent 分工协作 | IKS Health 的分工式多 Agent 适合行政流程；PHA 的星型路由适合单一入口导航 |
| 企业级 RBAC/多租户 | 个人项目没有真实用户量；面试时说清楚产品定位就行 |
| 商业规模（万级用户）| 个人项目，合理 |

## 四、我们不差的（主动说）

| 能力 | 同类产品的现状 | PHA 现状 |
|---|---|---|
| **多协议分层（MCP/A2A/AG-UI/ANP）** | 所有产品都没有这么清晰的协议分层 | ✅ 四层边界清晰，面试时说这个 |
| **RAG 有四组消融** | Color Health / IKS Health / Intercom Fin 都没有披露评测细节 | ✅ MRR 0.95 + 拒答 fpr=0.0 |
| **幂等性双通道（STATE_DELTA + PAGE_UPDATE）** | 所有产品都没有这个设计 | ✅ 按幂等性设计双通道 |
| **负结果照实记录** | 没有产品会公开说"测出来是负的" | ✅ 故事 10 + 重排 local_hit 负收益 |
| **三层路由 + layer3 LLM 兜底** | Intercom Fin 是意图分类 + 简单路由；Linear 是触发式 | ✅ 三层都有实现，不是概念 |
| **HITL 区分三种动作** | 大多数产品只做"确认弹窗" | ✅ `__interrupt__` 三选项是协议设计 |

## 五、最值得补的三件事（投出产出比最高）

| # | 事项 | 投入 | 面试价值 |
|---|---|---|---|
| ① | **补一条"提交医生复核"的 HITL 选项** | ~2h | "我在医疗 AI 的闭环上有设计：AI → 医生复核 → 用户"（对标 Color Health） |
| ② | **量化自主率（模拟环境）** | ~2h | "模拟环境下 X% 的问题不需要人工介入"（对标 Intercom Fin） |

| **合计** | | **~5h** | |

这三件事加起来的面试价值：体现了**医疗 AI 的合规意识** + **评测思维** + **可量化的工程判断**。
