# 用户视角原则 (3 条铁律 + 反例库)

> **目的**: 避免每次反复重新思考"用户能不能看懂". 把规则记下来, 写代码时一眼扫过.

---

## 三条铁律

### 铁律 1: 0 程序员术语

> 用户不认识的字眼, 一律不要让他看见.

| 程序员说 | 用户视角改 |
|---|---|
| OCR | 自动识别 / 读取图片内容 |
| 解析 / 提取 / 抽取 | 读取 / 整理 / 看懂 |
| API / SDK / Qwen-VL | (完全不出现) |
| 字段 / KV / 节点 | 内容 / 标签 / 卡片 |
| 已识别 / 未识别 / 排队中 | (删, 见铁律 2) |
| 提取信息 / 重新提取 / 重新跑 | (改全自动, 见铁律 3) |
| token / context / prompt | (完全不出现) |

---

### 铁律 2: 0 状态暴露

> 用户上传附件后, 自动就有内容. 中间状态属于开发者心智, 不该给用户看.

| 之前 | 现在 |
|---|---|
| "OCR 已识别 1/1" | (删) |
| "已 OCR 提取" | (删) |
| "暂未识别" | (删) |
| "识别中… (3/5)" | (删, 用户不需要这个数字) |
| "暂无正文" 按钮 "从附件 OCR 提取" | "上传附件后, 图片内容会自动出现在这里" |

**为什么**: 用户看不到中间状态 = 不焦虑 = 不点那些莫名其妙的按钮.

---

### 铁律 3: 0 中间步骤按钮

> 用户视角的流程是: 上传 → 看到内容 → 改内容 → 保存. 任何中间按钮都是"打断"。

| 之前 (用户要点的) | 现在 (全自动) |
|---|---|
| "提取信息" 按钮 | 后台识别, 上传即合并 |
| "重新提取" 按钮 | (删) |
| "OCR 跑一次" 按钮 | (删) |
| "解析" Tab | (删, 解析字段已经在基础页顶部) |
| "OCR 原文" Tab | (删, 用户不需要看 raw) |

**例外**: "编辑" / "删除" / "新增" 这种**用户的主操作**, 必须保留按钮.

---

## 应用: 健康档案页

### 现在的健康档案页 (阶段48-22 v6)

**用户视角完整流程**:
```
1. 打开页面 → 看到档案列表 (按重要性 / 日期排好)
2. 点任意档案 → 弹窗默认 "基础信息" Tab
3. 顶部 "图片识别到的信息" 卡片 → 一眼看病人字段 (姓名/床号/诊断)
4. 切换 "正文" Tab → 看结构化医学报告 (段落卡 + 免疫组化 chips)
5. 切换 "附件" Tab → 看上传的图
6. 想改? → 点 "编辑" → 改正文 → 保存
7. 想加附件? → 拖文件 → 后台自动识别 → 自动加到正文
```

**用户从头到尾不知道 OCR / 提取 / 解析** 是什么.

## 反例库 (这次对话踩过的坑)

### 反例 1: "请上传检查报告以解析"

```
❌ "请上传检查报告, 我们会解析其中的内容"
✅ "上传后, 图片里的内容会自动出现在正文里"
```

### 反例 2: "OCR 已识别 1/1"

```
❌ "OCR 已识别 1/1"
✅ (删 — 用户不关心这个数字)
```

### 反例 3: "提取信息" 按钮

```
❌ [提取信息] ← 用户必须点的中间步骤
✅ (后台上传即合并, 用户根本看不到这个按钮)
```

### 反例 4: 945 字 raw OCR 文本给用户

```
❌ <Typography>{detail.content}</Typography> ← 一坨字
✅ 渲染结构化 ParsedView (病人字段网格 + 段落卡片 + 免疫组化 chips)
```

### 反例 5: 详情页用 "OCR" 命名 Tab

```
❌ Tab: [基础] [正文] [附件] [📋 解析] [OCR]
✅ Tab: [基础] [正文] [附件]   ← 删 2 个用户不看的
```

### 反例 6: 列表卡片摘要显示全部 KV

```
❌ "病理号: 病人编号: 报告状态: 已审核 姓名: 性别: 男 年龄: 65岁 ..."
✅ "胃窦恶性肿瘤"  ← 智能提取主次
```

## 体检清单 (写代码时扫一眼)

每次新增 UI 元素时, 问自己:

- [ ] 用了程序员术语吗? → 改
- [ ] 暴露了中间状态吗? → 删
- [ ] 让用户点了不必要的按钮吗? → 全自动
- [ ] 显示了 raw 数据吗? → 渲染结构化
- [ ] Tab 命名用户能看懂吗? → 不懂就改

如果任意一项答"是, 但必要" → 在体检表里记录, 跟用户确认.

---

## 例外情况 (什么时候可以保留程序员术语)

1. **开发者文档** (`docs/` 目录) — 用户看不到, 随便写
2. **错误日志** (`console.error`) — 用户看不到
3. **管理员面板** — 如果有, 内部用, 不用迁就
4. **后端 API 路径** (`/api/v2/health-records`) — 用户看不到 URL

**不例外**: 任何写到 `frontend/src/` 下的字符串, 全部走铁律.
