# 开发节奏: 集中重整 + 验收

> **规则**: 不再"东改一点西改一点". 每次改动都按下面这套节奏走.

---

## 1. 流程 (4 阶段)

```
[A] 体检           →  发现问题列表 (写进 docs/HEALTH_RECORDS_UX_AUDIT.md)
   ↓
[B] 优先级选择     →  用户用 AskUserQuestion 选"哪一项先改"
   ↓
[C] 集中改动       →  只改选中那一项 (或一个紧密相关的小批量)
   ↓
[D] 签收           →  用户看效果, 决定 "通过" 或 "下一项"
```

**一个流程产出 1 个 commit**. 不在同一个 commit 里混改多项.

---

## 2. 何时做体检

- 用户反馈"开发太乱 / 这里改一点那里改一点"时
- 一个阶段(OCR 重构 / 用户视角重构 / 术语清理)做完后
- 一周内累积了 5+ 个 commit 时

**体检不需要全量返工**, 而是**主动扫描**所有页面, 找出"我还没听到反馈但用户视角下其实不优雅"的小项, 提前消化.

---

## 3. 体检表 (10 项以内 / 一次体检)

体检发现的问题写进 `docs/HEALTH_RECORDS_UX_AUDIT.md`, 每条记录:

```markdown
- [ ] #N 简述问题 (高/中/低严重度)
  - 现象: 截图/描述
  - 建议: 一句话修法
```

**严重度说明**:
- **高**: 用户立刻能感觉到、影响主流程的
- **中**: 用户能感觉到、但不影响主流程
- **低**: 开发者自查发现, 用户不会主动反馈

体检表永远保持 ≤ 10 项. 改完的就 ✓ 掉, 累积多了就重新写一版.

---

## 4. 用户视角原则 (3 条铁律)

> 任何要"显示给用户"的 UI 都必须过这 3 条.

1. **0 程序员术语**: OCR / API / 提取 / 解析 / 字段 / 节点 → 全改成 识别 / 读取 / 整理 / 内容 / 标签 / 卡片
2. **0 状态暴露**: 已识别 / 暂未识别 / 处理中 → 删, 用户不关心中间状态
3. **0 中间步骤按钮**: "提取信息" / "重新提取" / "重新跑解析" → 改后台全自动, 用户不点

完整版见 `docs/USER_PERSPECTIVE_PRINCIPLES.md`.

---

## 5. 提交节奏

### 一次 commit = 一个工作单元

```
❌ 不允许: "fix: OCR 解析器; refactor: 列表卡片; ui: 统计卡"
✅ 允许:   "fix(stage48-22 v6): OCR 解析器 — 拆'肉眼所见:' 多键一行"
```

### commit message 模板

```
<type>(<scope>): <用户视角的简短改动说明>

<针对用户截图/反馈的诊断>

<做了什么: 高 level 描述, 不是逐行 patch>

<效果: 改完后用户能看到什么>

<节奏备注: 这是体检表第几项, 后面还要走什么>
```

### 类型

- `feat` 新功能
- `fix` 修 bug
- `refactor` 内部重整
- `docs` 文档
- `chore` 杂事

---

## 6. 什么时候停下来 (Stop 条件)

- 体检表里没有"高严重度"项了 → 停下来, 问用户"下一项要做什么"
- 同一个文件改到第 5 处 → 停下来, 重新评估是不是该整体重写
- 一个 commit 超过了 200 行 diff → 停下来, 拆

---

## 7. 反例 (这次对话的前 5 个 commit)

> 这次对话从对话 1 到 5, 是**反例**:

```
commit 1: 用户看到 945 字 raw 文本 → 把 OCR 藏起来
commit 2: 用户看到'这是什么' → 改提示文案
commit 3: 用户说'用户不知道 OCR' → 重构不暴露术语
commit 4: 用户说'看不到 滑动不了' → 改 dialog 滚动
commit 5: 用户说'这没展示全' → 修后端解析器
```

**问题**:
- 每个 commit 都是被动响应, 没有主动体检
- 没文档沉淀: 同样的用户视角原则改一次忘一次
- 没优先级: 改 A 又改 B, 改动范围乱

**正例**:
```
doc 1: DEVELOPMENT_RHYTHM.md (这份文档)
doc 2: HEALTH_RECORDS_UX_AUDIT.md (体检表 + 优先级)
doc 3: USER_PERSPECTIVE_PRINCIPLES.md (3 条铁律)

体检 1: 主动扫 10 项 → 选 1 项 → 改 → 验收 → 选下一项
体检 2: ...
体检 3: ...
```

---

## 8. 现在的工作模式

**下一次反馈进来时**:
1. 先打开 `docs/HEALTH_RECORDS_UX_AUDIT.md` 看现在哪些 ✓ 哪些还没
2. 把新反馈加进体检表 (如果有的话)
3. 用 AskUserQuestion 选优先级
4. 改 → 验收 → 进入下一项

**不跑题**: 用户说"用户看不到", 不要立刻改代码, 先看体检表是不是已经记录了. 如果体检表已经记录, 选它改. 如果没记录, 先加进体检表, 再选它改.
